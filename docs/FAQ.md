# 常见问题与故障排查

[返回首页](../README.md) · [使用手册](USER-GUIDE.md) · [安装](../INSTALL.md) · [DIY 配置](CUSTOMIZATION.md) · [已知问题与测试状态](TESTING.md)

先区分问题发生在哪里：GitHub 上看不到图片、浏览器配置器报错、命令行应用失败、DSH 里没有变化，分别对应不同步骤。不要通过删除整个 DSH 数据目录来排查皮肤。

## 下载与安装

### 下载后怎么还是只有一张背景图？

皮肤列表的 `preview/desk.png` 本来就是一张背景预览，并不等于仓库图册。完整展示在 [COMPONENTS.md](COMPONENTS.md)、`docs/components`、`docs/artwork` 和 `evidence` 中。旧的 v1.1.1 Release 仓库 ZIP 保留首次发布内容；要拿到后来增加的 100 张图片和新手册，请下载 [当前完整仓库](https://github.com/Xtsaixuexi/whale-desk-skin/archive/refs/heads/main.zip)。

### GitHub 上点击 HTML 为什么只看到代码？

GitHub 文件页面主要展示源代码。下载并完整解压仓库后，在本机浏览器打开 `docs/gallery.html` 查看画廊，打开 `tools/editor.html` 使用配置器。不要只保存这一个 HTML；其依赖文件也要保留。

### DSH 皮肤列表没有鲸伴

按顺序确认：安装的是正确 DSH 数据目录；最终路径直接是 `skins/whale-desk/skin.json`；目录没有多套一层；`assets` 和 CSS 完整复制。随后完全退出并重开 DSH。自定义 `DSH_HOME` 时，默认用户目录未必是应用实际使用的位置。

### 列表里有皮肤，但应用后仍是旧样式

确认选中的名称是鲸伴，并检查已安装副本 `skin.json` 的版本。若刚使用配置器，查看命令输出的 `skin` 路径：默认只改仓库内的副本，可能尚未把它安装到 DSH。重新选择皮肤、重启后仍无变化，再记录宿主版本和具体页面排查。

### 有背景，但字体、图标或某些页面不对

先完整复制整个 `whale-desk`，不要只复制图片或一个 CSS。代码区域保留等宽字体属于预期；部分插件或宿主版本的类名变化则可能导致选择器不再匹配。仓库检查可以发现文件丢失，不能证明实际页面每个选择器都生效。

### GitHub 图片偶尔打不开

先点开单张图片确认，再下载完整仓库离线浏览。图片加载失败与皮肤是否安装成功是两件事；仓库图册不会在运行时从 GitHub 取图，皮肤使用随包本地资源。

## 配置器与应用命令

### 我在网页改好了，为什么 DSH 不变？

网页只编辑内存中的选项。需要依次“导出 JSON → 执行配置命令 → 安装生成的皮肤 → 在 DSH 重新选择”。关闭网页不会自动保存，也不会将改动直接传给 DSH。

### 顶栏题字变了，“探索未至之境”怎么没变？

它们是两个位置。`motto` 只控制顶栏的小句子，配置器目前没有欢迎标题或品牌字标的文字字段。不要通过无限加长题字去覆盖主标题；窄窗口会截断题字。

### 选了“不放图片”，为什么角色还在？

确认当前“位置”选的是哪一项。隐藏宠物设置插画不会隐藏首页鲸鱼娘；隐藏主侧栏也不会关闭桌宠。若要去掉整个首页背景，选择“首页背景 → 不放图片”，导出并应用。配置器关闭水彩小摆件，也只影响对应装饰，不会关闭所有图片。

### 报错与处理对照

| 提示或现象 | 含义 | 处理 |
| --- | --- | --- |
| `node` 无法识别 | 当前终端找不到 Node.js | 准备 Node.js 22+，重新打开终端，用 `node --version` 确认 |
| 找不到 `scripts/configure.mjs` | 当前目录不在完整仓库根目录，或只下载了安装包 | 在包含 `scripts`、`tools`、`skins` 的目录打开终端 |
| JSON 文件不存在 | 下载位置或文件名不同 | 使用实际完整路径并加引号，检查浏览器是否加了编号 |
| 配置必须是 JSON 对象／解析失败 | 内容不是合法 JSON | 不要混入 Markdown 代码围栏、注释或尾随逗号；优先从配置器重新导出 |
| 未知配置字段 | 使用了程序不支持的字段 | 对照 [参数表](CUSTOMIZATION.md#参数与影响范围)，不要自行添加主标题或远程图片字段 |
| 输入框宽度或字号范围错误 | 数值超出支持范围，或写成了字符串 | 宽度填 560–1100 的整数，字号填 14–20 的整数，不带 `px` |
| 题字最多 24 字 | 内容太长或含控制字符 | 缩短题字，移除换行与制表符 |
| 对比度低于 4.5 | 指定文字色与底色过于接近 | 同时检查浅色和深色方案，调整文字与底色 |
| 仅支持本地图片／格式不匹配 | 使用了网址、SVG、GIF 或扩展名与内容不符 | 在网页中选择真实 PNG、JPEG、WebP，不只修改扩展名 |
| 图片总量过大／配置超过 64 MB | 内嵌图片使 JSON/CSS 过大 | 降低图片体积，减少自选图数量 |
| 目录名必须是 `whale-desk` | 目标路径不是皮肤目录本身 | `--skin` 指向直接包含 `skin.json` 的 `whale-desk` |
| 目标不是 Whale Desk v2 皮肤 | manifest ID 或格式不符 | 检查目标，避免指向 `diy-journal` 或 `skins` 上级目录 |
| 拒绝符号链接 | 工具不写入链接目录或链接文件 | 使用实际且独立的普通皮肤文件夹 |
| DIY 标记不完整或不在文件末尾 | 手动改动造成覆盖段损坏 | 先保存当前文件，再用确认正常的备份恢复；不要继续堆叠标记 |
| 发布检查提示个人 DIY 内容 | 正在检查含个人配置的皮肤 | 自用不需发布检查通过；准备发布时先保存 JSON，再恢复默认 |

### 我导入一个小示例后，自选图片没了

配置导入和应用按整套参数处理，缺省字段会回到默认值，不是增量合并。请先导出保存自己的完整 JSON，再试示例；需要合并时在配置器重新选图或编辑已有完整配置。

### 为什么皮肤列表预览图没跟着我的 DIY 更新？

配置工具改的是 CSS 覆盖段和个人 JSON，不改 `preview/desk.png`。列表预览、文档示例与实际应用的自定义背景是三个不同来源。看到旧预览图不能单独证明 DIY 失败。

## 画面、桌宠与兼容性

### 输入框还是比我想象的宽，或小窗口看不出改动

参数控制最大宽度，不保证任何窗口都严格显示这个值。窗口较窄时可用空间先限制宽度；请在同一窗口尺寸下比较，并确认实际已安装副本使用了新配置。如果标题、人物和输入框出现遮挡，记录窗口大小与缩放比例后报告。

### 深色下有些字不清楚

目前静态示例已记录账户卡、展开触发通知、问答面板等处的对比度问题。可先切换宿主浅色主题，避免将调高某一个颜色当作完整修复。问题范围与实机状态见 [TESTING.md](TESTING.md)。本次说明书更新不包含这些样式修复。

### 任务看板、自动化或远程访问入口不在

图册展示的是相应组件的静态样式，是否有功能入口取决于 DSH 与已启用插件。皮肤不额外提供这些能力，也不会替你开启远程访问或更改权限。先确认宿主已有相应功能，再排查其外观。

### 桌宠没有变化／不能动

本仓库没有桌宠动画包。首页人物和宠物设置画都是静态图片；浮动桌宠由 DSH 自己管理。请在实际宠物功能中选择已安装资源，动作或拖动问题应与皮肤背景分开排查。当前仓库没有承诺桌宠完整交互已测试通过。

### 可以用原作者的配置插件吗？

上游 DIY Journal 设置插件是独立项目，原本写入 `diy-journal`。鲸伴使用独立 ID `whale-desk`，请使用本仓库的离线配置器。双图拼贴、胶带、拖拽旋转与 DSH 内嵌编辑入口当前不在鲸伴工具范围内。

### 能在其他操作系统或新版 DSH 使用吗？

文件结构可供其他环境参考，但已观察环境是 Windows、DSH `0.2.1-rc.2`、Skin Center `0.4.8`。未做验证的系统或版本不能标成已兼容；宿主组件类名改变后可能需要更新 CSS。

## 恢复与问题报告

### 怎样找回之前喜欢的改稿？

先找之前导出的 JSON；也可以检查目标皮肤目录的 `.whale-desk-backups`。每个备份保存应用前的 CSS，以及当时存在的配置 JSON。首次应用前没有 JSON 是正常的。恢复旧参数用 `--config`，恢复当前默认用 `--reset`，回退整个版本则恢复完整文件夹备份。

### 怎样报告一个能复现的问题

在 [GitHub Issues](https://github.com/Xtsaixuexi/whale-desk-skin/issues) 中说明以下内容，截图先去除账户、余额、会话正文和私人路径：

```text
问题标题：例如，深色主题下账户卡文字难以阅读
系统：
DSH 版本：
Skin Center 版本：
鲸伴版本：
主题：浅色 / 深色
窗口尺寸与系统缩放：
是否使用个人 DIY：是 / 否；改了哪些参数
发生位置：
复现步骤：1. ... 2. ... 3. ...
期望表现：
实际表现：
恢复默认后是否仍发生：
截图或报错原文：
```

如果只有配置报错，提供参数和错误文字即可，不必上传含私人照片的完整 JSON、整个 DSH 数据目录或账户配置。提交 issue 供维护者排查，不代表工坊已收录或问题已修复。
